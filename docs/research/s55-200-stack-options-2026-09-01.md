# S55-200 Stack-Specific Research Findings — 2026-09-01

## Contract

External results create hypotheses only. They contribute **0 t/s** until the
same DS4 binary, GLM-5.3 Q2 model, M5 Max, real ~200K context, exact semantics,
and balanced sustained-decode gate show a win. M0 confirms current width-2 MTP
is slower near 200K, but remains diagnostic and contributes 0 t/s.

Research used Tavily, Firecrawl, and Context7 through the local rotator. No
Exa/Elasticsearch research MCP was exposed in this session.

## Measured M0 result

At actual context 197,395, current MTP measured 44.1838 ms/token (22.6327 t/s)
versus MATCHED-STATE NOMTP at 39.7307 ms/token (25.1694 t/s), an 11.2081% MTP
penalty. MTP commits 1.83929 tokens/cycle at 81.2666 ms/cycle. The 55 t/s cycle
budget is 33.4416 ms, leaving 47.8250 ms/cycle. This confirms the diagnostic
loss; the existing width-2-versus-serial floating-state gap still blocks an
exact-semantics `MTP_AUTO` release.

## Highest-value decision

Run indexed `n=1` versus `n=2` first. It directly tests the newly
observed long-context MTP failure mechanism, costs less than a new shader, and
can falsify the entire sparse two-row-verifier project before implementation.
If the ratio is near 2x, build the exact indexed skinny-2 path around DS4's
existing packed formats and state semantics. If the ratio is near 1.2x, stop
and attribute the rest of the MTP cycle before touching matmul kernels.

## H24 first 200K measurement

At actual position 197,396, the real pending MTP pair was timed in-process with
one warm-up per arm and eight balanced ABBA/BAAB samples per arm. Indexed n=1
was 54.708 ms mean (95% CI 54.226-55.189); indexed n=2 was 75.301 ms mean
(74.792-75.810). The ratio is 1.3764x and absolute excess is 20.594 ms (excess
95% CI 19.893-21.294). The original >=1.7x hypothesis is false, but both kill
gates pass: ratio >1.3 and excess >4 ms. This tax is 25.34% of the measured MTP
cycle. Removing it completely is only an arithmetic ceiling of about 30.31 t/s,
not S55 progress. An exact implementation must reduce n=2 below 67.111 ms
(<=1.2267x n=1) merely to beat current MATCHED NOMTP.

The request-level 7.49 t/s from this diagnostic is rejected: sixteen scored
direct-forward probes intentionally serialized inside a 16-token request.

The full ladder confirms a smooth context term:

| Position | Indexed n=1 | Indexed n=2 | Ratio | Excess |
|---:|---:|---:|---:|---:|
| 4,728 | 38.766 ms | 44.470 ms | 1.1471x | 5.704 ms |
| 32,171 | 40.573 ms | 48.457 ms | 1.1943x | 7.884 ms |
| 64,134 | 43.227 ms | 53.443 ms | 1.2364x | 10.217 ms |
| 128,130 | 48.963 ms | 64.137 ms | 1.3099x | 15.173 ms |
| 197,396 | 54.708 ms | 75.301 ms | 1.3764x | 20.594 ms |

The excess fit is `5.336719 + 0.077099 * context_Ktokens` ms with R2=0.999917;
n=2's context slope is 1.91635x n=1. Source inspection explains the candidate:
`ds4_gpu_glm_indexer_scores_batch_grouped_tensor()` selects its tiled shared-key
kernel only for `n_tokens >= 8`. Width-2 therefore dispatches the scalar batch
kernel over `(pooled context rows, token)` and rereads the same indexer-key row
for both token workgroups. The next experiment is a GLM-5.3-only exact pair
kernel that stages one key row once but preserves each token's float operation
and reduction order. Reusing the existing half tiled kernel is rejected because
it changes arithmetic and wastes six of eight query rows.

The first exact-pair screen at position 4,728 passed byte-for-byte equality for
the complete two-row hidden output and vocabulary logits. Eight balanced
same-process samples measured 44.223 ms baseline versus 43.633 ms candidate,
a 0.590 ms / 1.33% reduction with conservative paired 95% CI
[-1.168, -0.012] ms. This is below the H25 retention threshold at short
context; the candidate proceeds only to the predeclared 197K decision point,
where the duplicated key-read term is materially larger.

At actual position 197,402, the decision A/B passed the same byte-for-byte
hidden/logit gate and measured 86.781 ms baseline versus 68.769 ms candidate.
The exact-pair kernel removed 18.013 ms / 20.76%, with conservative delta 95%
CI [-19.053, -16.972] ms. The server recorded exactly one request and no queue;
a separate local 4K server started 73 seconds after this A/B completed, so it
did not overlap the measurement. This confirms H25 as a retained candidate,
not S55 progress: a clean real-decode A/B is still mandatory.

Independent GPT-5.6 Sol max review kept the kernel opt-in and rejected
default-on pending clean real-decode evidence. The measured M5 Max path is
enabled with `DS4_METAL_GLM53_INDEXER_SCORE_PAIR_EXACT=1`; the disable variable
remains an emergency kill switch. A direct Metal regression now forces both
implementations and finds all 514 score values bit-identical with FP32 cache and
all 514 bit-identical with FP16 cache, including the pooled visibility edge.
The isolated short snapshot test finds all 267,106,276 serialized bytes exact.
At the canonical ~197K state, the same 16-cycle comparison preserves the five
single-token / eleven two-token schedule, full logits every cycle, and all
4,885,013,984 serialized bytes. The diagnostic scanner now uses a thread-local
override and no longer mutates the caller's process-global kill switch.

A subsequent real 197K M0 run produced raw MTP 25.915 t/s versus MATCHED NOMTP
22.939 t/s, but is rejected: the NOMTP control spread was 15.264%, above the 5%
gate, while substantial unrelated system and indexing load was present. All
1,422 token IDs plus the output and trajectory hashes match the prior baseline
M0 exactly. The speed attempt grants zero S55 credit and must be repeated under
a stable process state.

A second exact 197K request also completed and matched the same token, output,
and trajectory hashes. Raw H25 MTP was 23.011 t/s at 79.929 ms/cycle versus
MATCHED NOMTP 21.085 t/s, but the result is again rejected: control spread was
14.707% and worst adjacent movement 14.513%. The time-local discriminator is
paging, not temperature: swap rose from 11.4 to 13.6 GiB during the 65-second
decode window while macOS reported no thermal or performance warning. Planned
DS4 residency is 95.96 GiB; idle host usage before the failed run was 31.2 GiB,
versus 23.4 GiB before the valid M0. This explains measurement invalidity but
earns 0 t/s; a third identical rerun is not justified until paging is absent.

## Profiler implementation decision

Apple exposes command-buffer GPU start/end time after completion and optional
timestamp counter sampling.[^apple-command-debug] The exact M5 Max probe found
the timestamp set and sample buffer but no dispatch-boundary sampling support.
DS4's existing stage profiler ends and waits at every boundary, so it remains
rejected. The topology-neutral H26 fallback labels existing command buffers and
reads `GPUStartTime`/`GPUEndTime` at their existing completion wait. At actual
position 197,623, OFF/ON hidden state and logits were exact; mean/median overhead
was +0.41%/+0.62% with paired delta CI [-0.202, 0.910] ms. A 16-cycle replay
matched all 4,885,013,984 serialized state bytes. This accepts the fallback as a
whole-command-buffer diagnostic. It rejects H26 as a macro-region profiler:
selected-layer region names share one whole indexed-forward span and cannot rank
KDA versus routed MoE. It receives zero throughput credit.

## Sustained-runtime warning

Fresh same-stack field evidence reports a different failure mode: on an M5 Max,
ordinary GLM-5.3 Q2 chunks stayed near 27 t/s at about 60K context, but some
50-token chunks stalled for up to 232 seconds while a large SSD download was in
progress.[^ds4-931] This is not proof of an engine defect or an S55 result. It
does mean request-average dashboard throughput cannot distinguish slow kernels
from long inter-token stalls. The 60-minute gate must retain per-block elapsed
time and maximum inter-token gap plus compressor/swap/page-in and competing-I/O
telemetry; all stalls remain inside sustained decode time.

## Explicit non-candidates

- Do not port MLX, llama.cpp, or another engine into DS4. Their results only
  identify shapes and mechanisms to measure locally.
- Do not claim theoretical bandwidth, GPU utilization, cache, TTFT, prefill,
  free RAM, or model-size reduction as S55 progress.
- Do not raise `dense_limit=4096` without exact indexed-state equivalence.
- Do not start tree speculation until the current width-2 indexed cost and
  GLM KDA recurrence are understood.
